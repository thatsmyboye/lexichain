# Lexichain for iOS

An [Expo](https://expo.dev) (SDK 58) app that packages the Lexichain web game for the App Store.

**Android is not supported yet.** The Android settings and code in this project are kept for later,
but nothing builds or submits for Android: see "Android" at the end.

## How it works

The app is a native shell around the deployed game. It loads
`https://lexichain.banton-digital.com` in a full-screen WebView and adds what a browser tab can't do:

| Feature | Where |
| --- | --- |
| Native haptics on iOS and Android (the web build can only vibrate on Android) | `src/bridge.ts` → `playHaptic` |
| System share sheet for result text and the PNG result card (Android WebViews have no Web Share, and no WebView can download files) | `src/bridge.ts` → `shareText`, `shareImage` |
| Links to other sites open in an in-app browser instead of replacing the game | `GameScreen.tsx` → `onShouldStartLoadWithRequest`; `openExternal` |
| Android back button steps back through the game's screens | `GameScreen.tsx` → `hardwareBackPress` |
| Status bar and system background follow the game's light/dark theme and skin | `theme` message |
| Native splash screen held until the game's first screen has painted | `ready` message |
| Offline screen with retry when the first launch has no connection | `src/OfflineScreen.tsx` |
| Recovers if the OS kills the web content process in the background | `onContentProcessDidTerminate`, `onRenderProcessGone` |
| Offline play after the first launch: the game's service worker runs in the app (on iOS through `WKAppBoundDomains`) | `app.config.ts` |

The web side of the bridge is `src/lib/nativeApp.ts` in the web project. It only switches on when
the page runs inside this app; in a browser everything behaves as before. The two files define the
same message shapes; change them together.

Because the app loads the live site, **a web deploy updates the app too**. No store release is
needed for gameplay changes. A new store build is only needed when something in this `mobile/`
folder changes.

## Run it

```bash
cd mobile
npm install
npx expo start
```

Scan the QR code with **Expo Go** to try it on a phone. Expo Go doesn't apply this app's
`Info.plist`, so offline play on iOS only works in a real build.

To point the app at another deployment (a Vercel preview, or your dev server on the same network):

```bash
EXPO_PUBLIC_WEB_URL=https://your-preview.vercel.app npx expo start
```

A development build (`npm run ios` / `npm run android`, or `eas build --profile development`) is
needed for anything Expo Go doesn't cover. The `ios/` and `android/` folders are generated by
`expo prebuild` and are gitignored. Configure native behavior in `app.config.ts`, never by editing
them.

Before committing: `npm run typecheck` and `npm run doctor`.

## Build and publish with EAS

One-time setup (needs an [Expo account](https://expo.dev/signup) and an
[Apple Developer Program](https://developer.apple.com/programs/) membership):

1. Confirm the identity in `app.config.ts`. **`APP_ID` (`com.bantondigital.lexichain`) is permanent
   once published.**
2. `npx eas-cli@latest login`. The Expo project already exists and its ID is set as
   `EAS_PROJECT_ID` in `app.config.ts`, so there is no `eas init` step.
3. Create the app record in App Store Connect (bundle ID above).

Builds (EAS manages signing credentials; let it create them when asked):

```bash
npm run build:preview      # installable iOS test build (ad hoc)
npm run build:production   # iOS store build
npm run submit             # upload the latest production build to App Store Connect
```

Build numbers increment automatically (`eas.json`: `appVersionSource: remote`). EAS counts them per
platform, and only iOS is built, so only the iOS number moves. Bump `APP_VERSION` in `app.config.ts`
for each store release.

## Store listing checklist

The web project already provides these:

- **Privacy policy URL:** `https://lexichain.banton-digital.com/privacy`. The contact address shown
  there is `PRIVACY_CONTACT_EMAIL` in `src/pages/PrivacyPage.tsx`.
- **In-app account deletion** (App Store Guideline 5.1.1(v), Google Play account-deletion policy):
  My Account → Delete my account. It calls the `delete_my_account` database function
  (`supabase/migrations/20261123120000_add_delete_my_account.sql`), which is live in production.
  Google Play also asks for a deletion URL: use the privacy policy's "Deleting your data" section.
- **Data collected** (App Store privacy labels / Play data-safety form): email address, user ID,
  display name and gameplay content (scores, words), linked to the account, used for app
  functionality only, no tracking, deletable in the app. Nothing is stored for players without an account.
- **Encryption:** declared exempt (`ITSAppUsesNonExemptEncryption = false`).
- **Age rating:** no ads, purchases, user chat or user-generated content beyond display names.
- **Screenshots, description, keywords, support URL:** not in the repository; prepare them in each
  console. `public/icons/og-image.png` and the logo files in `docs/brand/` can help.

Icons and splash images in `assets/` are generated from `docs/brand/` by
`node scripts/generate-native-app-icons.mjs` (run from the repository root).

### App Review: minimum functionality

Apple rejects apps that are "just a website" (Guideline 4.2). This one goes further than a browser
tab: native haptics, the system share sheet, offline play, native splash and theme integration,
and no browser UI. In the review notes, mention that the game is fully playable offline after the
first launch and without an account.

## Android

Android is not supported at first. To keep it out of builds and out of EAS's build numbering:

- `platforms` in `app.config.ts` lists only `ios`;
- the `build:preview`, `build:production` and `submit` scripts pass `--platform ios`.

The `android` block in `app.config.ts`, the Android profile settings in `eas.json`, the Android
icons, and the Android code paths (back button, native padding) are kept so the platform can be
added later. To turn it on:

1. Add `"android"` to `platforms` in `app.config.ts`.
2. Change the three scripts in `package.json` to `--platform all`.
3. Create the app in the [Google Play Console](https://play.google.com/console) (package name
   `com.bantondigital.lexichain`). The first upload to Google Play must be done by hand there; an
   API key for `eas submit` only works once the app exists.
4. Fill in the Play data-safety form from the "Data collected" entry above, and give the privacy
   policy's "Deleting your data" section as the account-deletion URL.

Android production builds were started on November 24, 2026 before this decision, so EAS's Android
build number is already past 1.
